# LuliVerify mobile verification

Businesses publish backend-owned workflows and integrate the SDK using a publishable key and release ID. Customers complete verification inside mobile apps or through the hosted widget. The SDK owns launch, navigation and cleanup; the host receives advisory results. No merchant secret belongs on a device.

Audience: customers completing identity/business verification, often using a phone one-handed. Fields, options, validation, evidence requirements and outcomes come from the backend. Real liveness requires a provider; dummy liveness remains visibly test-only.

The user approved a native redesign, not a copy of the web builder: primary #1F3FE2, Geist, rounded controls and consistent outline icons. Preserve accessibility, large text, keyboard access and visible error recovery.
